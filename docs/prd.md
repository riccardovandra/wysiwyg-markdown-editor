# Product Requirements Document - Markdown WYSIWYG

**Author:** Riccardo
**Date:** 2025-12-10

## Input Context

**Product Vision (from video transcript):**
A VS Code extension providing WYSIWYG markdown editing focused on writing flow rather than syntax memorization. Free and open-source alternative to paid markdown editors.

**Core Problem:**
Writers of technical docs break their creative flow when switching between raw markdown and preview, or when trying to remember syntax for tables, images, and links.

**Target Users:**
- Developers, programmers, QA engineers
- Product managers, project managers
- Anyone using VS Code variants (Windsurf, Cursor, etc.) for documentation

**Key Features Identified:**
1. WYSIWYG markdown editing (not just preview)
2. Always-visible toolbar for accessibility
3. Easy table manipulation (add/delete rows/columns via context menu)
4. Mermaid diagram preview inline
5. Screenshot paste with auto-save to relative paths
6. Drag-and-drop image support
7. Code blocks with language selection
8. Copy selection as markdown
9. Split view for source inspection
10. Medium.com-inspired readable typography

**Differentiator:** Free, open-source, flow-focused—no paywalls for "advanced features"

## Executive Summary

**Markdown WYSIWYG** is a VS Code extension that transforms how developers interact with markdown files—particularly those generated by AI tools. Rather than bouncing between raw syntax and preview panes, users read and edit markdown in a clean, Medium.com-inspired interface while maintaining full fidelity to the underlying format.

### What Makes This Special

1. **AI-output friendly** — Designed for the modern workflow where AI generates markdown and humans review/refine it
2. **Reader-first design** — Comfortable typography and layout that makes reading long documents pleasant
3. **Flow-preserving editing** — Toolbar always visible, tables editable via context menus, screenshots auto-saved with relative paths
4. **Free and open-source** — No paywalls for features that should be standard

## Developer Tool Specific Requirements

### VS Code Extension Architecture

**Extension Type:** Custom Editor Provider
- Registers as an alternative editor for `.md` files
- Uses VS Code's Custom Editor API to provide WYSIWYG view
- File system sync handled by VS Code's document model

**UI Approach:** WebView-based
- Rich text editing requires WebView (VS Code native APIs don't support WYSIWYG)
- Editor framework: TipTap or Milkdown (ProseMirror-based, markdown-native)
- Toolbar rendered within WebView

### Platform Compatibility

| Platform | Priority | Support Level |
|----------|----------|---------------|
| VS Code | Primary | Must work |
| Cursor | Secondary | Should work (VS Code fork) |
| Windsurf | Secondary | Should work (VS Code fork) |
| Other VS Code forks | Tertiary | Best effort |

**Minimum Version:** VS Code 1.74+

### Installation & Distribution

**Phase 1 (MVP):** Manual VSIX installation
- Build produces `.vsix` file
- Users install via `Extensions: Install from VSIX...`

**Phase 2 (Post-MVP):** VS Code Marketplace
- Public listing for easier discovery and updates

### Technical Sync Architecture

**Markdown → WYSIWYG:**
1. Read `.md` file content
2. Parse to AST (using `remark` or similar)
3. Render as editable HTML in WebView

**WYSIWYG → Markdown:**
1. Capture editor changes
2. Serialize editor state back to markdown
3. Sync to VS Code document model
4. Save triggers file write

### Implementation Considerations

- **No external dependencies** for end users (all bundled in extension)
- **Performance target:** File open < 500ms for typical documentation
- **Memory:** Reasonable footprint for large files (lazy rendering if needed)

### Risk Mitigation

| Risk Type | Risk | Mitigation |
|-----------|------|------------|
| Technical | Markdown ↔ WYSIWYG sync complexity | Use proven library (TipTap/Milkdown) instead of building from scratch |
| Technical | WebView performance on large files | Implement lazy/virtual rendering if needed |
| Technical | Edge cases in markdown parsing | Leverage battle-tested parsers (remark ecosystem) |

## Functional Requirements

### File Operations

- **FR1:** User can open any `.md` file in WYSIWYG view via right-click context menu
- **FR2:** User can open any `.md` file in WYSIWYG view via command palette
- **FR3:** System automatically syncs edits to the underlying markdown file
- **FR4:** User can save the document (Cmd/Ctrl+S triggers file write)

### Document Rendering

- **FR5:** System renders markdown headings (H1-H6) as visually distinct styled text
- **FR6:** System renders bold text as visually bold
- **FR7:** System renders italic text as visually italic
- **FR8:** System renders unordered lists with bullet styling
- **FR9:** System renders ordered lists with number styling
- **FR10:** System renders links as clickable styled text
- **FR11:** System renders fenced code blocks with syntax highlighting
- **FR12:** System detects code block language and applies appropriate highlighting

### Editing Capabilities

- **FR13:** User can click any text element to place cursor and edit
- **FR14:** User can select text for formatting operations
- **FR15:** User can create new lines and paragraphs
- **FR16:** User can delete text and elements
- **FR17:** User can undo/redo edits

### Toolbar & Formatting

- **FR18:** System displays a persistent formatting toolbar
- **FR19:** User can apply bold formatting via toolbar
- **FR20:** User can apply italic formatting via toolbar
- **FR21:** User can apply heading levels via toolbar
- **FR22:** User can create lists via toolbar
- **FR23:** User can insert links via toolbar
- **FR24:** User can insert code blocks via toolbar

### Table Support

- **FR25:** System renders markdown tables with pipe-delimited format
- **FR26:** User can insert tables via toolbar with configurable rows and columns (dialog)
- **FR27:** User can add rows below and columns to the right of existing tables
- **FR28:** User can delete entire tables via toolbar

### Task Lists

- **FR29:** System renders task list items (`- [ ]` and `- [x]` syntax) as interactive checkboxes
- **FR30:** User can toggle task list checkbox state by clicking

### YAML Frontmatter

- **FR31:** System detects and extracts YAML frontmatter from markdown files
- **FR32:** User can view and edit frontmatter in a dedicated visual editor with toggle visibility

### Editor Customization Settings

- **FR33:** User can configure editor appearance via `showCard` setting (card layout with shadow)
- **FR34:** User can configure content padding via `contentPadding` setting (compact/medium/spacious)
- **FR35:** User can configure text size via `textSize` setting (small/medium/large)
- **FR36:** User can configure line height via `lineHeight` setting (tight/compact/normal/relaxed)
- **FR37:** User can configure accent color theme via `accentTheme` setting (indigo/blue/purple/teal/neutral)
- **FR38:** User can disable accent color for bold text via `disableBoldAccentColor` setting

## Non-Functional Requirements

### Performance

- **NFR1:** File open time < 500ms for documents up to 10,000 lines
- **NFR2:** Typing latency imperceptible (< 50ms input-to-render)
- **NFR3:** Toolbar actions complete within 100ms
- **NFR4:** Save operation completes within 200ms

### Reliability

- **NFR5:** Zero data loss—all edits are preserved accurately when saved
- **NFR6:** Markdown output is valid and equivalent to input (no corruption)
- **NFR7:** Graceful handling of malformed markdown (render what's possible, don't crash)

### Compatibility

- **NFR8:** Functions correctly in VS Code 1.74+
- **NFR9:** No degradation in VS Code forks (Cursor, Windsurf)
- **NFR10:** Works on macOS, Windows, and Linux

### Usability

- **NFR11:** No learning curve—behaves like expected rich text editor
- **NFR12:** Keyboard shortcuts match standard text editing (Cmd/Ctrl+B, etc.)
